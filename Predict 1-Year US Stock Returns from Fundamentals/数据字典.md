# 数据字典 —— Predict 1-Year US Stock Returns from Fundamentals

> 生成时间：2026-09-12
> **数据来源**：比赛官方 `train.csv` / `test.csv` / `sample_submission.csv`（本地实际下载后逐列统计）
> **字段含义来源**：比赛官方 Data Description 页面（英文原文）+ 本地实测分布校验
> **方法说明**：形状、类型、缺失率、分位数、异常值计数、重复行检测，全部由脚本在本地真实数据上跑出；字段业务含义以官方描述为准。
> **本表特殊标记**：凡是**官方描述与实测数据不符**或**官方未提及的风险**，均以 ⚠️ 标出（共 6 处），这些是官方文档里看不到的。

## 一、概览

| 文件 | 行数 | 列数 | 时间范围 | 备注 |
|---|---|---|---|---|
| `train.csv` | 23,070 | 39 | `period_start` 2019-01-01 ~ 2022-12-31 | 含目标列 `return_pct` |
| `test.csv` | 8,520 | 36 | `start_year` 全部为 2024 | **无** `return_pct`、**无** `period_start` / `period_end` |
| `sample_submission.csv` | 8,520 | 2 | — | 列名 `id, return_pct`，值全为 `0.0` |

- 数据来源：SEC 财报（10-K / 10-Q），由 Atlantis Data Solutions 提供
- 覆盖约 **2,200 家**美国上市公司（train 1,734 只、test 2,200 只）
- 一行 = 一只股票 × 一个季度观测

**结构差异（很重要）**：`test.csv` 比 `train.csv` 少 3 列 —— `period_start`、`period_end`、`return_pct`。
也就是说**测试集没有给你持有期起止日期**，只有 `start_year = 2024`，你需要自己推断每个季度。

### 官方明确提示的 4 件事

1. train（截至 2023-12-31）与 test（自 2024-01-01 起）之间是**刻意留出的时间间隔**，用来防止时序泄漏
2. 特征**存在缺失值**，处理缺失是本题的一部分
3. 收益是**肥尾**的，两个方向都存在极端离群值
4. 同一只股票**可能有多条观测**（每年最多 4 个季度）

## 三、字段类型汇总

| 类型 | 字段 | 说明 |
|---|---|---|
| **整数 int64** | `id`、`start_year` | 纯标识/年份，不参与建模 |
| **字符串** | `ticker`、`period_start`、`period_end` | 代码与日期需转成日期型才能用 |
| **分类（数值编码）** | `sector_code` | 0–10 共 11 类，可当类别特征，**不要当连续数值** |
| **连续浮点 float64** | 其余 **33 个**特征 + `return_pct` | 注意单位混杂：有"百分比"（%、margin、yield、growth）、有"倍数"（ratio）、有"美元金额"、有"股数" |

⚠️ **单位陷阱**：33 个特征里，**百分比、倍数、美元金额、股数四种量纲混在一起**。
`total_assets` 是 10⁹~10¹² 量级，`current_ratio` 是 0~200 量级，`gross_margin` 是百分比。
直接丢进线性模型/距离类模型会被量纲大的字段完全主导，**必须先做标准化**（或用对量纲不敏感的树模型）。

## 四、⚠️ 数据质量问题清单（官方文档未提及）

以下 6 项都是在本地真实数据上核出来的，官方 Data Description **没有说明**：

### 1. `test.csv` 缺少持有期日期列
`test` 只有 `start_year = 2024`，**没有 `period_start` / `period_end`**。而 train 有。
→ 你必须自己按季度推断测试行的持有窗口（这也是为什么第 3、6 名方案都把"财季还原"当作独立步骤）。

### 2. `eps_basic` / `eps_diluted` 疑似单季度口径，与 TTM 字段不匹配
实测校验：`net_income_ttm ÷ (eps_basic × shares_diluted)` 的**中位数是 3.01、75 分位是 4.13** —— 明显接近 4。
以 AAPL 那一行为例：TTM 净利润 1,019 亿、摊薄股本 162 亿股 → 推算每股 ≈ 6.3 美元，但 `eps_basic` 只有 **1.54**。
→ **`eps_*` 是单季度 EPS，而 `net_income_ttm` 是滚动 12 个月净利润**。两者不能拿来互相验算，混用会出错。

### 3. `dividends_ttm` 的单位与官方描述不符
官方写的是 "Trailing 12-month dividends **per share** ($)"（每股分红）。
但实测**中位数是 2.76e7**（2760 万），非缺失值里有 **4,019 行大于 1 万**。
以 AAPL 为例 `dividends_ttm` = 147.34 亿 —— 这是**总金额**，不是每股。
→ **官方描述有误**，按"总美元金额"理解。

### 4. 存在 32 行完全重复的数据
用除 `id` 外的所有列做去重检测，发现 **32 行完全重复**，全部来自两只股票：**ET** 和 **PLD**，各有 16 组重复（每个 `period_start` 恰好 2 行，且两行所有字段完全相同，只有 `id` 不同）。
→ 这两只股票在训练集中被重复计入，**如果做样本权重或统计，会把它们的权重算成 2 倍**。

### 5. 财务比率存在大量物理上不可能的值
"比率类字段出现 -138 万倍、13 万倍、1.25e10 倍的取值"，在经济含义上不成立（通常是分母接近 0 或负值导致）：

| 字段 | 负值行数 | 超过 10⁴ 的行数 | 最大值 |
|---|---|---|---|
| `pe_ttm` | 5,219 | 86 | 1.25e10 |
| `price_to_book` | 1,044 | 83 | 5.27e6 |
| `gross_margin` | — | — | 137,639（毛利率 13 万 %） |
| `roe` | 4,617 | 88 | 3.36e6 |
| `net_margin` | 4,874 | 12 | 104,247 |
| `debt_to_equity` | — | — | 69,786 |

→ **必须做缩尾（winsorize）或改用分位数/排序**，否则这些脏值会直接毁掉模型。

### 6. 目标列存在极端离群值（与榜单争议直接相关）
`return_pct` 的分位分布：

| 分位 | 值 |
|---|---|
| 最小 | -99.17% |
| 1% | -80.20% |
| 25% | -19.79% |
| 50% | 3.50% |
| 75% | 33.83% |
| 95% | 118.08% |
| 99% | 299.17% |
| 99.9% | 1,241.34% |
| 最大 | **10,571.11%** |

→ 中位数只有 3.5%，但最大值超过 1 万 %。**前 0.1%（23 行）的样本贡献了总 MSE 的 73.3%**。
→ 论坛上已有参赛者指认其中包含**标签损坏**（某只股票收益被记为 +18,299,901%）并要求主办方复核。**建模前必须处理这些极值。**

## 五、使用建议（基于以上核查）

| 环节 | 建议 |
|---|---|
| 目标列 | 先缩尾（如 1%/99% 分位或 ±100%），或改用**截面分位数/排序**当目标 |
| 特征标准化 | 33 个特征量纲混杂，线性/距离类模型**必须标准化**；树模型可省 |
| 高缺失字段 | `dividends_paid_ttm`(93%)、`dividend_yield`(72%)、`dividends_ttm`(71%)、`gross_margin`(62%)、`inventory`(50%) 慎用；`dividends_paid_ttm` 建议转成 0/1 哑变量 |
| `eps_*` | 记住是单季度口径，与 `*_ttm` 字段不可混算 |
| `sector_code` | 当**类别特征**用，缺失的 ~0.5%/~1.3% 可单独设一类或按公司历史行业填补 |
| 重复行 | ET / PLD 各 16 行重复，去重或降权 |
| 验证方式 | 测试集是 2024 年、**完全在训练区间（2019–2022）之外** → **禁止随机交叉验证**，用按 `period_start` 的时序切分 |
| 提交 | 恰好 **8,520 行**，列名 `id, return_pct` |

## 附：本文数字的复现方式

- 数据：`kaggle competitions download -c predict-1-year-us-stock-returns-from-fundamentals`
- 统计：pandas 逐列计算 `dtype` / `isna().mean()` / `nunique()` / 分位数 / 异常值计数
- 重复检测：`df.drop(columns=['id']).duplicated()`
- EPS 口径核验：比较 `net_income_ttm ÷ (eps_basic × shares_diluted)` 的分位数（中位数 3.01 → 接近 4，判定为季度口径）
- 单位核验：取 AAPL 一行做人工比对（营收/净利润/分红/股本数量级交叉验证）
- 字段含义：比赛官方 Data Description 页面（MCP `list_competition_pages` 抓取）
