## 正文

### 一、概述

作者在本场比赛中获得 **第 6 名**，私榜最终分数 **4421.10130**，一共提交了 **217 次**并做了大量实验。

比赛要求用来自 SEC 财报的财务基本面，预测美国上市股票的未来一年收益。训练集包含 **2019–2022 年的 23,070 条"股票-季度"观测**，测试集包含 **2024 年的 8,520 条匿名化观测**。

这是一个格外困难的问题，因为股票收益噪声大、非平稳，并且**被极少数极端结果强烈影响**。由于评估指标是**均方误差（MSE）**，**一次对"多倍股"的错误预测，就足以主导整个分数**。

### 二、核心挑战

测试集的公司用这样的匿名标识表示：`STOCK_0001`、`STOCK_0002`、`STOCK_0003`……

这切断了每一行测试数据与它真实公司代码之间的直接联系。

然而，会计报表里包含**高度独特的数值组合**。一家公司的营收、总资产、股东权益、负债、存货、商誉、股本和盈利能力比率，可以充当一个**财务指纹**。

作者方案背后的关键洞察是：

> **不要只把每一行测试数据当成一个普通的特征向量，而应该尝试用它的 SEC 财报指纹，去识别它背后到底是哪家公司、哪个财季。**

### 三、方案架构

最终流水线包含六个主要阶段：

1. 外部财务数据口径统一（harmonization）
2. 多轮公司指纹匹配
3. 财季（持有期）还原
4. 市场价格收益重构
5. 置信度与撞车控制
6. （原文未展示第 6 项，从后文推断为"以基准提交为锚的预测替换策略"）

#### 1. 外部财务数据口径统一

作者用 SEC 与 EDGAR 的季度数据建立了一个参考数据库。流水线会自动在附带的数据集中搜索：

- 股票代码或公司标识
- 财季列
- 营收、净利润、总资产、股东权益
- 流动资产与流动负债、长期负债
- 商誉、存货、分红、股本

由于不同数据源的命名规则不一致，作者实现了一个**字段口径统一层**，把它们转换成统一表示：`ticker / period / revenue_ttm / net_income_ttm / total_assets / stockholders_equity / current_assets / current_liabilities / long_term_debt / goodwill / inventory / shares_outstanding / shares_diluted`

主要的那张 EDGAR 季度参考表包含**约 42,000 条观测、超过 1,700 家公司**。

#### 2. 多轮公司指纹匹配

单一匹配规则不够可靠，因此作者设计了一套多阶段的"身份识别"系统。

**Pass 1：严格财务指纹匹配**
先用**总资产的对数**筛出候选公司，再用多个会计字段的"精确匹配 + 近似精确匹配"打分。打分重点考察：

- 会计数值的精确匹配
- 近似精确匹配
- 派生比率的一致性
- 相对"第二佳候选公司"的**唯一性**

主要的派生比率校验包括：`ROE = 净利润 / 股东权益`、`ROA = 净利润 / 总资产`、`净利率 = 净利润 / 营收`

只有当**最佳候选比其它候选领先足够大的差距**时，才认可这家公司。

**Pass 2：比率辅助匹配**
第二遍放宽了对会计字段的要求，但要求盈利能力比率的一致性更强。这样在保持高精度的同时提高了覆盖率。

**Pass 3：公司层面的链式匹配**
有些单个季度因为缺失值或财报重述而很难识别。与其逐行独立匹配，作者改成**比较某个匿名股票所对应的完整多季度序列**。当这一整串资产、权益、营收等数值都能和某个真实代码对上时，才认可这家公司。

**Pass 4 / Pass 5：原文未展示。**

**Pass 6：历史版本的公司披露值匹配**
SEC Frames 通常只暴露最新披露的数值，但比赛数据可能取的是"后来被修正或重述之前"的数值。为此，最后一个匹配阶段去搜索**历史版本的公司披露值**——任何该公司该报告期曾经披露过的数值，都可以作为证据。

#### 身份识别的验证

作者通过**把训练集中已知的股票代码藏起来、再尝试从财务特征里把它还原出来**，来验证匹配系统。主要结果如下：

| 匹配组件 | 验证结果 |
|---|---|
| 严格指纹的 ticker 精度 | 99.40% |
| 严格指纹的财季精度 | 99.93% |
| 第二遍（比率辅助）的 ticker 精度 | 99.55% |
| SEC Frames 的 ticker 精度 | 97.57% |
| Frames 链式匹配精度 | 97.84% |
| 历史版本匹配器在已评估行上的精度 | 100.00% |

注意：**这些数字只在"该方法成功产出身份"的那些行上计算，衡量的是条件精度，而不是整体覆盖率。**

#### 3. 归属权与撞车控制

逐行独立匹配会把**同一个真实代码分配给多个匿名股票**。为防这一点，作者加了多层控制：

- 公司层面的归属权校验
- 优先采信严格指纹匹配
- 拒绝与更强的股票级证据相冲突的映射
- 撞车清除（collision purging）
- 只有当"兄弟季度"在财务上彼此一致时才做传播
- 把"已核实的映射"与"无法核实的社区映射"分开

流水线最初映射了**约 98% 的测试行**，但在做收益重构之前，把较弱和有冲突的映射删掉了。

最终被采纳的行按置信度分层：

| 层级 | 含义 |
|---|---|
| `fp` | 严格指纹 |
| `fp2` | 第二遍指纹 |
| `chain` | 公司序列匹配 |
| `sec` | SEC Frames 匹配 |
| `secv` | 历史版本 SEC 披露值匹配 |
| `map_hi` | 高置信度映射 |
| `ann` | 年报匹配 |
| `uni` | 唯一兼容公司 |

#### 4. 财季（持有期）还原

光识别出公司还不够，每一行还需要**正确的一年持有期的起止日期**。作者用以下信息构建财务日历：已知的训练期日期、EDGAR 报告期、SEC 申报日期、逐季度的外部收益文件、历史财年规律。

做法是：由起始日期生成"约一年后"的预期结束日，再在一个允许窗口内对齐到最近的已知财季日期。

在训练集上，还原出的结束日期：

- **98.99% 的行完全正确**
- **99.04% 的行误差在 3 天以内**

#### 5. 市场价格收益引擎

历史价格用 **Yahoo Finance** 获取，取不到时用 **Stooq** 兜底。价格层处理了：代码格式差异、拆股、分红、缺失交易日、退市或更名证券、API 限流、以及为可复现性做的缓存。

对每条观测，价格取**在所需日期当天或之前最近的那个交易日**（并设定了允许的最大间隔）。

作者测试了几种收益定义：

- **拆股调整后的价格收益**：用原始收盘价做拆股调整，保持"只算价格"的口径。
- **调整后收盘价收益**：当拆股调整后的原始序列不可得或不一致时使用。
- **分红调整**：使用调整后收盘价时，把估算的分红贡献**扣除掉**，让重构值更接近比赛的"价格收益"目标。

**收益引擎的验证**（用训练集中已知的代码和日期）：

| 指标 | 结果 |
|---|---|
| 覆盖的训练行 | 22,221 |
| 覆盖率 | 96.3% |
| 训练集 MSE | 8.122 |
| 训练集 MAE | 0.215 个百分点 |
| 误差在 1 个百分点内的预测占比 | 96.2% |

这说明：**只要代码和期间是对的，价格收益的计算本身是高度准确的。**

#### 6. 以基准提交为锚的预测策略

**完全用重构结果提交风险太大**，因为哪怕只有少量身份识别错误，也会带来灾难性的平方误差。所以作者用一份**已有的强提交作为锚**（基准），只有在满足以下条件时，才用重构收益替换基准预测：

- 存在有效的价格序列
- 代码和期间通过了置信度校验
- 该收益落在其置信度层级所允许的范围内
- 对较弱层级而言，与基准预测的差异不能过大
- 该代码不在"由训练集推导出的黑名单"里

置信度最高的指纹层级允许更大的自由度；SEC 类和映射类层级受到更严格的限制。

最终 notebook 相对基准提交**改动了 2,569 行**。替换诊断如下：

| 诊断项 | 值 |
|---|---|
| 修改行数 | 2,569 |
| 平均绝对修改幅度 | 1.42 个百分点 |
| 最大修改幅度 | 223 个百分点 |
| 超出 ±200% 的预测数 | 159 |

### 四、什么没有奏效

**纯基本面回归**
树模型集成和常规的表格模型**都无法接近最强的排行榜成绩**。基本面变量确实包含一些截面收益信息，但已实现的一年期收益依然极度嘈杂，而且目标里包含极大的离群值，使得 MSE 尤其难做。

**激进地提高身份覆盖率**
在**不**同步提高精度的前提下扩大映射覆盖率，**通常会让排行榜成绩变差**。对这个任务而言，身份识别的**精度比原始覆盖率更有价值**。

**全局预测截断（clipping）**
把所有极端收益都截断，看起来很诱人，因为该指标对大的误差惩罚极重。但是**有些极端收益是真实的**。删掉一个被正确重构出来的多倍股，可能比保留它更糟。

**逐季度独立匹配**
对每一行单独匹配会产生身份撞车和前后不一致的季度归属。**公司层面的序列匹配更稳定。**

### 五、公榜与私榜的表现差异

公榜和私榜的结果差异显著。这是意料之中的，因为**相对少量的极端收益观测，就足以主导任意一个划分上的 MSE**。

私榜暴露出了几个弱点：

- 残余的身份识别错误
- 错误的季度归属
- 未能解决的代码变更
- 被继承下来的极端预测
- 公榜/私榜两个划分之间的分布差异

尽管最终私榜分数明显差于最好的公榜实验，这个方案仍然拿到了**总排名第 6**。这印证了一条重要的教训：

> **在一个肥尾的金融预测问题里，平均验证精度是不够的。最重要的行，往往是那些罕见的、因为身份或期间错误而产生几百甚至几千个百分点收益差的观测。**

### 七、主要教训

**1. 先重新定义问题，再优化模型**
最大的提升来自认识到：**匿名化的财务报表可以充当公司指纹**。

**2. 精度可能比覆盖率更重要**
在普通的分类任务里，覆盖率从 80% 提到 95% 可能很有价值。但在**肥尾的 MSE** 下，几个错误的身份就能把所有收益抹平。

**3 / 4：原文未展示。**

**5. 公榜表现不等于私榜安全**
公榜可能奖励一小批正确的极端预测，而私榜里可能包含**不同的尾部观测**。
